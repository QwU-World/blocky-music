# Blocky Music: рабочий порядок

- Перед изменениями прочитай `DEVELOPMENT.md` и используй его карту подсистем. Не перечитывай весь проект без необходимости.
- Это основной мод. Внешние демонстрационные UI-сборки A/B/C/D не изменять, пока пользователь явно не попросит.
- Во время правки запускай `tools/blocky-build.ps1 Compile`; для ресурсов — `Check`.
- Для готовой сборки используй `Deploy`. Он собирает JAR, делает резервную копию, проверяет SHA-256 и отказывается менять профиль при запущенном Minecraft.
- `Full`/`FullDeploy` с `clean build` нужны только перед финальной выдачей рискованных изменений, после правок Gradle или при подозрении на грязный кэш.
- Не заявляй, что визуальное или сетевое поведение исправлено, без соответствующей проверки в Minecraft. Сборка и совпавший хеш подтверждают только код и доставку.
- Крупные классы разделяй постепенно при работе с конкретной подсистемой; не делай массовый рефакторинг одновременно с пользовательской функцией.
