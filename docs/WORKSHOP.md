# Workshop Beatmaps: мастерская карт по образцу osu!

Статус на 17.09.2026: **проектирование и фундамент.** Мастерская не построена и в игру не подключена.
Сделано только то, что описано в «Этап 0»: формат пакета v1, валидатор с атомарной установкой и его
регрессия. Ни одного нового экрана, клавиши, сетевого вызова или изменения голосования нет.

Номера строк ниже сняты 17.09.2026. `MusicBattleVoteScreen` в этот день параллельно правит другой агент,
поэтому для него искать по именам методов, а не по номерам.

## Задумка

Слова владельца, по пунктам:

1. **Клавиша открывает Workshop Beatmaps.** Там игрок заранее скачивает карты, и они сами
   устанавливаются. «Прям как в osu!».
2. **В подготовке к бою** кнопка «Серверные треки» становится «Workshop»: красивый список всех карт.
3. **Позже** кнопка «Пользовательские треки» становится «Установленные битмапы», то есть скачанные
   игроком карты.
4. **На сайте qwu.world** появляется мастерская как у osu!: отдельная страница на каждую карту,
   комментарии, оценки, автор, скачивание с сайта. Скачанный файл при открытии сам
   устанавливается в мод.

«osu! можно брать как полное вдохновение: концепт тот же, а мы мод для Minecraft». Требования владелец
будет дополнять, когда работа начнётся.

Источники первичные: код `ppy/osu` (lazer, коммит `f06789b`), `ppy/osu-web` (`fd32ef0`), вики
`ppy/osu-wiki` (`3661394`) и документация API v2. Колонка «Нам» говорит, что берём как есть, что
переделываем и что пропускаем.

## Словарь

| Наш термин | Аналог в osu! | Что это в коде и на диске |
|---|---|---|
| **Набор карт** (set) | beatmapset | Одна песня, обложка, автор, 1–16 чартов. На сайте числовой `setId`. На диске папка `ws_<setId>/` с манифестом `beatmap.meta`. |
| **Чарт** (сложность) | beatmap (difficulty) | Файл `ws_<setId>_<key>.json` в уже существующем формате экспорта редактора (`ClientTrackExporter.export`, `client/ClientTrackExporter.java:25`). Его `id` = имя файла без `.json` — это id трека в каталоге. В голосовании каждый чарт — отдельная карточка, как сегодня каждый трек. |
| **Ключ чарта** (`key`) | имя сложности в `[Metadata] Version` | `[a-z0-9_-]{1,32}`, например `hard`. Отображаемое имя сложности хранится отдельно, до 64 знаков. |
| **Трековая папка** | — | Существующая раскладка всех каталогов: `<root>/<id>/<id>.json + <id>.ogg + <id>_preview.png`. Установленный набор — это такая же папка, только чартов в ней может быть несколько. |
| **Ревизия** (`revision`) | `last_updated` | Целое ≥ 1, растёт на сайте с каждой опубликованной правкой. Для людей и для списка обновлений. |
| **Отпечаток содержимого** (`contentSha256`) | хеш набора lazer | SHA-256 по всем объявленным файлам (путь, размер, хеш) и по ссылке на аудио. Правка названия в манифесте его не меняет, правка чарта меняет. Ключ, по которому сервер и игроки сверяют «у нас одна и та же карта». |
| **Хеш чарта** | `checksum` / `MD5Hash` | SHA-256 файла чарта из манифеста. Ключ для локальной статистики (лучший результат, «последний раз играл»): переносится при обновлении, только если чарт не изменился. |
| **Автор** (`mapper`) | `user_id`, `creator` | Аккаунт qwu.world: `accountId` + имя на момент упаковки (до 32 знаков). Сегодня у опубликованного через Minecraft трека автор — ник и UUID Minecraft (`publishedBy`, `publishedByUuid`). Связка «аккаунт сайта ↔ UUID Minecraft» появится только на этапе аккаунтов. |
| **Политика аудио** | нет аналога | `included`: файл аудио лежит в пакете. `external`: в пакете только чарт и обложка, аудио игрок приносит сам, мод сверяет SHA-256 и длительность (`docs/LICENSING.md`). |
| **Статус** | ranked status | `pending` → `community` → `featured`, плюс `hidden` (скрыл автор) и `disabled` (снято модерацией или по жалобе). |
| **Установленные карты** | локальная библиотека lazer | `<gamedir>/music_battle_tracks/workshop/`. Клиентская, общая для всех миров и серверов. |

## Формат пакета

### Файл

- **Расширение `.blockymap`**, внутри обычный zip (deflate или stored). Сайт отдаёт его как
  `application/zip` с `Content-Disposition: attachment; filename="42 Artist - Title.blockymap"`, по
  образцу имени, которое отдаёт osu!.
- Архив **плоский** и повторяет установленную папку байт в байт, поэтому хеши из манифеста остаются
  верны и после установки:

```
beatmap.meta              манифест, JSON; имя не *.json намеренно
ws_42_easy.json           чарты, 1..16 штук, существующий формат экспорта редактора
ws_42_hard.json
ws_42.ogg                 Ogg Vorbis; только при audio.policy = included
ws_42_preview.png         обложка, необязательна
beatmap.sig               подпись сайта (Ed25519, 64 байта), необязательна, не объявляется в манифесте
```

Других имён быть не может: ни папок, ни иных расширений, ни регистра. `beatmap.sig` — единственная запись вне `files`:
подпись сайта над `bmw-sig-v1\n<setId>\n<revision>\n<contentSha256>\n`; в `contentSha256` не входит, при установке не
копируется, проверка подписи в моде — следующий этап. Предел записей в архиве поэтому 20 (16 чартов, аудио, обложка,
манифест, подпись). Всё это отбрасывается как
`UNSAFE_ENTRY_NAME` или `UNEXPECTED_ENTRY`.

### Почему именно так, а не новый формат

- **Чарт не меняется.** Это тот JSON, который пишет `ClientTrackExporter.export` и читает
  `MusicBattleTracks.readTrack` (`server/MusicBattleTracks.java:488-530`). Мод умеет его и сегодня.
- **Манифест не `.json`.** `MusicBattleTracks.loadDirectory` (`:263-273`) обходит каталог на глубину 2
  и считает чартом любой `*.json`. Файл `manifest.json` превратился бы в фальшивый трек `manifest`.
  Тот же приём, что `pack.mcmeta` у ресурспаков Minecraft.
- **Ссылки на ассеты уже в формате каталога.** Загрузчик разрешает `audio` и `preview` относительно
  корня каталога (`resolveAsset`, `:469-486`). Значит, в чарте `"audio": "ws_42/ws_42.ogg"` и
  `"preview": "ws_42/ws_42_preview.png"` работают без переписывания, и несколько чартов делят одно
  аудио. У набора с `external` аудио `audio` указывает туда, куда игрок должен положить свой файл.
- **Id не пересекаются.** `ws_<setId>_<key>` — максимум 55 знаков: меньше 96 (редактор, публикация),
  128 (загрузчик, кеш клиента, DJ-пакеты) и 255 (`TrackSummary`). Set id состоит только из цифр,
  поэтому разбор однозначен. `byId` берёт первое совпадение (`:282-284`), так что префикс `ws_`
  нужно зарезервировать: редактор и публикация должны его запрещать (Этап 2).

### Манифест `beatmap.meta`, формат 1

```json
{
  "format": 1,
  "setId": 42,
  "revision": 3,
  "title": "Song Title",
  "artist": "Artist",
  "mapper": { "accountId": 17, "name": "dragon4ik" },
  "audio": {
    "policy": "included",
    "size": 4816214,
    "sha256": "…64 hex…",
    "durationMs": 187000
  },
  "charts": [
    { "key": "easy", "difficulty": "Easy" },
    { "key": "hard", "difficulty": "Hard" }
  ],
  "files": [
    { "path": "ws_42.ogg",         "size": 4816214, "sha256": "…" },
    { "path": "ws_42_preview.png", "size": 208133,  "sha256": "…" },
    { "path": "ws_42_easy.json",   "size": 18422,   "sha256": "…" },
    { "path": "ws_42_hard.json",   "size": 30911,   "sha256": "…" }
  ]
}
```

Правила (реализованы в `workshop/BeatmapManifest.java`, проверены регрессией):

| Поле | Правило |
|---|---|
| `format` | Сначала читается только оно. Больше 1 → `UNSUPPORTED_FORMAT` («обновите мод»), даже если остальная форма уже другая. Неизвестные поля в пределах формата 1 игнорируются: добавлять поля можно, менять смысл нельзя. |
| `setId`, `revision` | Целые > 0. `1.5`, `"42"` и переполнение отвергаются, а не округляются. |
| `title` / `artist` | 1–128 / 0–128 знаков, без управляющих символов. |
| `mapper` | `accountId` > 0, `name` 1–32 знака (как `publishedBy` на диске). |
| `audio` | `policy` ∈ `included`, `external` (до 17.09.2026 назывались `licensed`, `chart_only`; старые имена отвергаются); `size` 1 Б – 128 МиБ; `sha256` — 64 строчных hex; `durationMs` 1 мс – 2 ч (потолок тиков чарта 144000). Объявляется **и для `external`**, чтобы проверить файл игрока. |
| `charts` | 1–16 штук, ключи уникальны, у каждого есть файл в `files`. |
| `files` | Только имена, выведенные из `setId`: чарты, `ws_<id>.ogg`, `ws_<id>_preview.png`. Лимиты: чарт 2 МиБ, OGG 128 МиБ, PNG 8 МиБ (как в `TrackPublicationManager.java:43-47` и `ClientTrackAssets.java:31-37`). |
| included | Файл аудио обязан быть в `files` с тем же размером и хешем, что в `audio`. |
| external | Файла аудио в `files` быть не должно: такое аудио сайт не раздаёт. |
| Манифест целиком | До 64 КиБ, строгий UTF-8, вложенность JSON не глубже 32. У Gson нет своего лимита, и пара килобайт `[[[[` уронила бы поток с StackOverflowError. |

**Отпечаток содержимого** (`BeatmapManifest.contentSha256()`): SHA-256 от UTF-8 текста
`"blockymap-content-v1\n"`, дальше по строке `file <path> <size> <sha256>\n` на каждый файл в порядке
сортировки путей, в конце `audio <policy> <size> <sha256>\n`. Сайт обязан считать его так же. Проверку
совпадения стоит добавить в регрессию сайта на эталонном пакете.

### Что проверяет установщик (`workshop/BeatmapPackage.java`)

Те же правила, что у уже существующих конвейеров недоверенных карт (`TrackPublicationManager` на
сервере, `ClientTrackAssets` на клиенте), но без классов Minecraft, чтобы их можно было проверять
отдельно:

1. Архив — обычный файл, не симлинк, не больше суммы всех лимитов плюс 1 МиБ.
2. Не больше 19 записей (16 чартов + аудио + обложка + манифест). Имя каждой записи —
   `beatmap.meta` или `[a-z0-9_-]{1,120}\.(json|ogg|png)`. Директории, `..`, абсолютные пути,
   `\` и `C:` не проходят.
3. Множество записей точно равно `files` + манифест.
4. Каждый файл читается потоком с жёстким потолком на объявленный размер. Размерам из заголовков
   zip мы не верим, SHA-256 должен совпасть точно.
5. Содержимое: первая страница OGG — заголовок Vorbis (Opus отвергается), длительность по последней
   granule совпадает с объявленной ±1 с. PNG: сигнатура, IHDR, не больше 2048×2048 и 4 194 304 px.
   Чарт: `id` = имя файла, `audio` и `preview` указывают в папку набора, `notes` — массив до 4096,
   `effects` — до 512.
6. Распаковка идёт в свежую папку `music_battle_tracks/.workshop_staging/set_*`. Она соседняя, а не
   внутри `workshop/`, чтобы сканер каталога никогда не увидел половину набора. После этого одно
   переименование в `workshop/ws_<setId>`. При обновлении старая версия сначала переименовывается в
   staging, а если второе переименование не удалось, возвращается обратно. При любой ошибке staging
   удаляется, прежняя версия остаётся нетронутой. Удаление возможно только ниже разрешённого
   корня, симлинки не разыменовываются, запись файлов идёт с `CREATE_NEW`.
7. Сообщения ошибок содержат только имена записей из архива, экранированные и обрезанные. Абсолютных
   путей в них нет (правило `MusicBattleTracks.displayPath/safeText`).

Чего установщик пока **не** делает, это следующие этапы:

- Не повторяет диапазонную санацию каждой ноты и эффекта (`TrackPublicationManager.sanitizeNotes/
  sanitizeEffects`, `:334`, `:365`). Их надо вынести в чистый помощник без `PacketDistributor` и
  вызывать и при публикации, и при установке. Это Этап 2. Сейчас структурная проверка плюс
  толерантный загрузчик (обрезка до 4096 нот и 512 эффектов, `:587-663`) — та же защита, что у
  карт из `my_tracks`.
- Не декодирует звук. Проверка OGG контейнерная, последнее слово за декодером игры.
- Для `ALREADY_INSTALLED` не пересчитывает хеши установленных файлов: сверяет манифест и размеры.
  Полная перепроверка — отдельное действие «Проверить файлы» в UI.

Что регрессия **не** доказывает. Она не может заставить второе переименование упасть, поэтому откат
старой версии в этом случае проверен только чтением кода. Раннюю остановку потока на объявленном
размере она тоже не отличает от поздней: запись больше объявленной отвергается как `SIZE_MISMATCH` в
обоих случаях. Мутационный прогон 17.09.2026 это подтвердил: поломки белого списка имён, сверки
SHA-256 и очистки staging регрессия ловит, а две названные — нет. И конечно, она не доказывает, что
синтетический OGG играет декодер Minecraft.

### Как пакет получается из трека игрока

Игрок сохраняет трек в редакторе, получается `my_tracks/<id>/` (`ClientTrackExporter`). Дальше
«Опубликовать в мастерскую»: загрузка на сайт по HTTPS, **не через Minecraft**. Сайт выдаёт `setId`,
прогоняет те же проверки (портированные в TypeScript), переписывает в чарте `id`, `audio` и `preview`
и **сам собирает** `.blockymap`. Игрок финальный пакет не собирает никогда, поэтому источник правды
по хешам — сайт. Для наборов с `external` аудио сайт хранит только SHA-256, размер и длительность аудио игрока, но не
сам файл.

## Установка

### Поток

```
Скачать      .part в music_battle_tracks/.workshop_downloads/, потолок размера, SHA-256 архива из API,
             прокси Minecraft (HttpUtil.downloadFile делает всё это сам)
Проверить    BeatmapPackage.readManifest → подтверждение → BeatmapPackage.install      [Этап 0, готово]
Установить   staging → одно переименование в workshop/ws_<setId>/                    [Этап 0, готово]
Учесть       перечитать манифесты workshop/ → состояние карточек → список «Установленные»
```

Всё, кроме последнего шага, идёт вне render thread (`Util.nonCriticalIoPool()`). Результат
применяется через `Minecraft.execute`.

### Где лежат карты относительно существующих каталогов

| Каталог | Путь | Кто пишет | Кто читает сегодня | Сторона |
|---|---|---|---|---|
| Мои треки | `<gamedir>/music_battle_tracks/my_tracks/` (`MusicBattleTracks.java:64-66`) | редактор | библиотека, редактор | клиент |
| Серверные | `<world>/blocky_music/server_tracks/` (`:68-78`, `:229-232`) | админ руками | голосование, DJ | сервер |
| Опубликованные | `<world>/blocky_music/user_tracks/user_<12hex>_<id>/` | `TrackPublicationManager.install` (`:277-332`) | голосование, DJ | сервер |
| **Установленные из мастерской** | `<gamedir>/music_battle_tracks/workshop/ws_<setId>/` | `BeatmapPackage.install` | **пока никто** | клиент |
| Staging мастерской | `<gamedir>/music_battle_tracks/.workshop_staging/` | `BeatmapPackage.install` | — | клиент |
| Кеш загрузок с сервера | `music_battle_tracks/.server_cache/<ns>/<trackId>/` (`ClientTrackAssets.java:235-254`) | передача боя | бой | клиент |

Правило, на котором легко ошибиться: **в одиночной игре интегрированный сервер и клиент живут в одной
JVM и делят статические кеши `MusicBattleTracks`.** Если добавить `workshop/` в `availableTracks()`
(`:275-280`), карты молча станут «серверными», но только в одиночной игре. Поэтому загрузчик мастерской
отдельный. Нужен `loadDirectory(Path, Source)` вместо `boolean userTrack`, с отдельным клиентским
списком. `availableTracks()` его не видит.

### Дубликаты и обновления

- **Один набор — одна папка.** Имя папки = `setId`, поэтому две версии одного набора существовать не
  могут. Это «владение по online id» из lazer.
- **Тот же пакет повторно:** манифест совпадает и все файлы на месте с нужными размерами →
  `ALREADY_INSTALLED`, ничего не пишется. Если файл пропал, пакет ставится заново.
- **Другая ревизия:** атомарная замена → `REPLACED`.
- **Индекса пока нет, и это сознательно.** Источник правды — манифесты в `workshop/*/beatmap.meta`
  (до 64 КиБ каждый): рассинхронизироваться с папкой они не могут. Кеш в памяти, пересканирование при
  открытии экрана. Отдельный файл понадобится только для состояния игрока (избранное, лучший результат,
  «последний раз играл») с ключом по хешу чарта. Класть его в корень `music_battle_tracks/` (он не
  сканируется), **не в `workshop/`**: там любой `*.json` станет чартом.
- **Проверка обновлений:** `POST /installed-check` со списком `(setId, revision, contentSha256)`. Если
  ответ новее, на карточке появляется «Доступно обновление». Id внутри файла мы не доверяем, как и lazer.
  Файл, скопированный у друга, связывается со страницей через `lookup` по `contentSha256`.
- **Локальные правки.** Установленные карты только для чтения. В редакторе появляется «Копировать в мои
  треки» (id с новым именем, `my_tracks`). Поэтому обновление никогда не затирает работу игрока. Это
  проще, чем предупреждение `LocallyModified` у osu!.
- **Темп x1.5/x2.** Сервер делает `<base>_x15.ogg`/`_x2.ogg` через FFmpeg рядом с исходником
  (`MusicBattleTracks.java:296-380`). У них другие байты и хеш, поэтому «у меня уже есть» совпадает
  только на x1.0. Проверка `ALREADY_INSTALLED` смотрит лишь на объявленные файлы, и лишние варианты ей
  не мешают. Замена набора их удаляет: они создаются заново.

### Как голосование увидит установленные карты

Сегодня список голосования приходит **с сервера**: `OpenVotePayload` строится из
`MusicBattleTracks.availableTracks()` в момент создания боя (`BattleManager.java:209`, `:287`, `:1193`),
до 512 записей без пагинации (`OpenVotePayload.java:23`). Голос принимается только за id из
`battle.tracks` (`BattleManager.java:516-528`). Сервер собирает runtime-чарт и стримит аудио со своего
диска. Отсюда три честных варианта, по возрастанию стоимости:

1. **«Мастерская» = карты, которые установил сервер.** Админ кладёт `.blockymap` или выполняет
   `/musicbattle workshop install <setId>`. Набор ставится тем же `BeatmapPackage` в
   `<world>/blocky_music/workshop/`, и сервер отдаёт его как любой свой трек. В `TrackSummary`
   добавляются `source`, `setId`, `contentSha256`; протокол повышается. Игрок, у которого набор уже
   установлен, передачу пропускает. Для этого бою нужна пара offer/answer по SHA-256, как у DJ
   (`DjPreloadOfferPayload`/`DjPreloadAnswerPayload`), и поиск в `workshop/` по хешу, а не по
   `trackId + имя` внутри namespace сервера (`ClientTrackAssets.java:235-254`).
2. **По запросу из списка Featured.** Вкладка листает API сайта прямо на клиенте, голос уходит как
   `(setId, key, contentSha256)`. Сервер скачивает набор сам, если это разрешено в его конфиге. Нужен
   исходящий HTTP у выделенного сервера: переключатель в конфиге и раскрытие на Modrinth.
3. **«Установленные» = карта клиента на чужом сервере.** Клиент предлагает `(setId, key, contentSha256)`,
   сервер проверяет её по API (вариант 2) и ставит у себя. Без API сервер знать карту не может: чарт
   чужой и непроверенный, а голосовать можно только за то, что у сервера на диске.

**`external` в мультиплеере.** Сервер аудио такого набора не имеет и получить его не может. Предлагаемое
правило: карту можно выбрать, только если **у всех участников** есть файл с тем же SHA-256. Мод аудио
карт с `external` аудио не пересылает. Пересылка «от игрока, у которого есть файл» — открытый вопрос: через
диск сервера Minecraft хостом становится его владелец (`docs/LICENSING.md`).

Голосование длится 60 с (`VoteTiming.VOTE_SECONDS`, `data/VoteTiming.java:15`), подготовка трека до
5 минут. Скачивать карту во время голосования нельзя. Можно между голосованием и стартом, и только
лицензированную.

## Открытие файла «в один клик»

### Что мод может, а что нет

**Двойной клик по `.blockymap` или ссылка `blockymusic://` в уже запущенный Minecraft не придут.**
Проверено по коду 1.21.1:

- Процесс запускает лаунчер, это `java` с jar-файлами. У него нет своего исполняемого файла, app bundle
  и установщика, который мог бы зарегистрировать тип файла или URL-схему. Одновременно может быть
  запущено несколько профилей (Modrinth App, Prism) с разными папками игры.
- В `net/minecraft/client/main/Main.java` (merged jar) есть только опции запуска (`quickPlay*`,
  `gameDir`, …). Single-instance IPC нет ни в vanilla, ни в NeoForge, ни в моде. JVM вне app bundle не
  получает от macOS событие «открыть документ».
- Единственный путь «файл из ОС → игра» — GLFW drop. `MouseHandler.onDrop` (`:188-190`) вызывает
  `Screen.onFilesDrop(List<Path>)` (`Screen.java:477`, по умолчанию пустой), **и только пока открыт
  экран**. В vanilla его переопределяет только `PackSelectionScreen` (ресурспаки). Отдельного события
  NeoForge для drop нет.

Непонятно, в какую папку игры класть. Localhost-слушатель — поверхность атаки (только 127.0.0.1, токен, полная валидация). Раскрытие «External system interactions» на Modrinth. Мод, который пишет в реестр, выглядит как вредонос и переживает собственное удаление |

### Рекомендация

- **Основной путь — A + B.** Браузер в игре с кнопкой «Установить», поиск принимает ссылку или ID.
  Это и есть «скачал заранее, и само установилось».
- **Для «скачать с сайта» — D + C.** На странице карты рядом с «Скачать .blockymap» короткая
  инструкция: «Откройте Мастерскую в игре и перетащите файл в окно или положите его в папку
  `workshop_inbox`». Установка всё равно идёт через `BeatmapPackage` с подтверждением.
- **Следующим шагом E**, когда появятся аккаунты: кнопка «Отправить в игру» закрывает желание
  «кликнул на сайте, и оно в игре» честнее, чем помощник.
- **F внутри мода не делать никогда.** Имеет смысл только как часть отдельного лаунчера QwU World,
  если такой появится.

### Решение владельца (17.09.2026)

Делаем **оба пути «из файла»**, плюс браузер A + B в игре:

1. **Перетаскивание (C).** Файл `.blockymap` бросают на окно игры, мод устанавливает его через
   `BeatmapPackage` и кладёт в `music_battle_tracks/workshop/`. Чтобы перетаскивание работало не только на
   экране мастерской, `onFilesDrop` переопределяется и на экране голосования, и в библиотеке треков.
2. **Двойной клик — маленький установщик QwU (F, отдельной программой, не в моде).** Двойной клик по
   `.blockymap` запускает установщик, он проверяет пакет тем же правилом, что и мод, и кладёт файл во
   «входящие» `music_battle_tracks/workshop_inbox/` нужной сборки. Мод подхватывает «входящие» при старте,
   при открытии экрана мастерской и лёгкой проверкой раз в несколько секунд, пока игра запущена, и
   показывает уведомление «Карта установлена». Оба пути сходятся в одной точке установки внутри мода.

Детали установщика:

- **Куда ставить.** Установщик сам ищет сборки с модом: просматривает папки известных лаунчеров (Modrinth
  App `profiles/`, Prism `instances/`, CurseForge `Instances/`, обычный `.minecraft`) и находит в `mods/`
  файл `blocky_music-*.jar`. Одна сборка — ставит молча, несколько — спрашивает и запоминает выбор.
  Тип файла и ссылку регистрирует установщик, а не мод: мод в системе ничего не регистрирует. Но раскрытие
  «External system interactions» на Modrinth всё равно нужно: мод запускает FFmpeg, обычно установленный вне
  папки игры (конвертация звука в редакторе, импорт osu!, копии 1.5x/2x на сервере), и на мгновение кладёт
  временный файл в системную временную папку (звук импортируемой карты, превью для загрузки). Текст раскрытия
  лежит в `MODRINTH-LISTING.md`.
- **Регистрация типа файла** делается установщиком при его установке: Windows — `HKCU\Software\Classes`
  без прав администратора, macOS — `CFBundleDocumentTypes` в `Info.plist`, Linux — `.desktop` + `xdg-mime`.
- **Язык.** Нативный бинарник (Go или Rust), без Java: у большинства игроков Java есть только внутри
  лаунчера. Размер цель — единицы мегабайт.
- **Безопасность.** Установщик не слушает сеть и не запускает код из пакета; пакет только копируется во
  «входящие», а распаковка и все проверки остаются в моде.

### Оценки: что на самом деле было у osu!

Предпосылка «osu! убрал оценки» первичными источниками **не подтверждается**:

- Вики (текущая HEAD) по-прежнему описывает оценку 1–10 после прохождения сложности в stable. Она
  показывается у Qualified, Ranked, Approved и Loved; 6+ считается положительной, есть график
  распределения ([Beatmap_information#L70-L78](https://github.com/ppy/osu-wiki/blob/36613947ce44cee6c34a62091e9c86743b604d26/wiki/Beatmap_information/en.md#L70-L78)).
  osu-web её рендерит ([stats.tsx#L68-L85](https://github.com/ppy/osu-web/blob/fd32ef0b68bac7973021c473fa52b3ecba1f39c6/resources/js/beatmapsets-show/stats.tsx#L68-L85)),
  `rating` есть среди сортировок и на сайте, и в lazer.
- В **lazer UI оценки так и не сделали**. Issue [ppy/osu#34735](https://github.com/ppy/osu/issues/34735)
  «Add back capability to rate beatmaps» открыт с 19.08.2025. PR
  [ppy/osu-web#13124](https://github.com/ppy/osu-web/pull/13124), влит 10.07.2026, добавил
  `GET/POST /api/v2/beatmapsets/{id}/ratings`. Правила там: 1–10, вход и чистая история, набор с
  таблицей рекордов, **нельзя оценивать свой**, повторный голос перезаписывает, рейтинг = среднее.
- Рядом с оценкой, а не вместо неё: **избранное** (одна кнопка, публичный счётчик, лимит 100 / 1000 для
  supporter), **hype** (10 на пользователя, возвращается через неделю, нужно 5 для номинации) и
  голосование Project Loved. Ничто из этого оценку не заменило.

**Нам:** сначала избранное (без гейта, питает фильтр «Избранное»). Оценки позже, и главное в них не
шкала, а гейт: оценивать может только аккаунт, который доиграл карту в бою (мод должен сообщить факт
прохождения, это телеметрия с раскрытием), свою карту оценить нельзя, голос перезаписывается, хранится
среднее и гистограмма. Hype и Loved не нужны, пока нет команды кураторов.

| `POST /api/v1/workshop/installed-check` | `{sets:[{setId, revision, contentSha256}]}` → какие обновились или сняты | `{updates:[…], disabled:[…]}` |
| `POST /api/v1/workshop/sets/{setId}/download` | Выдать ссылку на пакет. Пишет счётчик. Проверяет лимит и `download_disabled` | `{url (подписанная, 5 мин), size, sha256, fileName}`; `429` + `Retry-After`; `410` снято |
| `GET /api/v1/workshop/sets/{setId}/comments?sort=new\|old\|top&cursor=` | Посты темы форума, только чтение | `{items, cursor}` |
| `PUT/DELETE /api/v1/workshop/sets/{setId}/favourite` | Избранное | `{favourited, count}` |
| `POST /api/v1/workshop/device/code`, `POST …/device/token` | Привязка мода к аккаунту (device code): мод показывает код, игрок вводит его на `qwu.world/link` | `{userCode, verifyUrl, interval}` / `{token}` |
| `GET/DELETE /api/v1/workshop/queue` | «Отправить в игру» | `{items}` |
| `PUT /api/v1/workshop/sets/{setId}/rating` | Позже, с гейтом прохождения | `{rating, count, histogram}` |

Загрузка наборов — **только через веб-форму**, не из мода: там нужен ToS-чекбокс, выбор трека из
библиотеки и проверки.

**Соглашения.**

- `schema` в каждом ответе. Мод, получивший незнакомую схему, вежливо отказывается («обновите мод»),
  как `UNSUPPORTED_FORMAT`.
- Ошибки `{error:{code, messageKey}}`: `code` машинный, `messageKey` совпадает с ключом lang мода.
- `User-Agent: BlockyMusic/<версия> (Minecraft 1.21.1; NeoForge)`. Только HTTPS. Прокси Minecraft
  (`Minecraft.getInstance().getProxy()`). Таймауты. Сетевые вызовы вне render thread.
- Токен хранится в клиентском конфиге с правами только владельца, отзывается со страницы `/account`.
  Сессии там уже перечисляются.
- В логах сервера IP урезаны до /24 или /48, как в `qwu-api`.

**Уроки osu! про лимиты и трафик.**

- **Живым игрокам бесплатно и без счётчика, ботам тихий лимит.** Лимит на аккаунт в час и на IP для
  гостей. У osu! в коде по умолчанию 10 (supporter 20) в час, продовые значения не опубликованы. Нам
  стартовать мягче, скажем 60 в час на аккаунт и 20 на IP, числа держать в конфиге. 429 всегда с
  `Retry-After`, в игре локализованное сообщение.
- **API файлы не стримит:** подписанная ссылка на хранилище за CDN, `download_disabled` проверяется до
  выдачи ссылки.
- **Размер держим на входе:** жёсткие лимиты мода + лимит сайта для лицензированного аудио (по образцу
  «5 МБ + 10 МБ за минуту»). Наборы с `external` аудио весят килобайты, поэтому основной трафик — библиотека
  лицензированных треков и обложки (публикатор и так сжимает их до 1024 px).
- **Курсор, а не номера страниц.** Дубликаты отбрасывает клиент.
- **Гости:** решает владелец. Можно, в отличие от osu!, дать листать без аккаунта, а скачивание
  требовать с аккаунтом. Тогда лимиты и счётчики привязаны к людям.
- **Не считать «готовым»** путь 429 и лимиты, пока их не прогнали на живом бэкенде.

## Лицензии и модерация

Опирается на `docs/LICENSING.md` (решение от 17.09.2026) и `docs/RELEASE-MODRINTH.md`.

### Аудио

- **Сайт раздаёт аудио только из белого списка:** лицензированные, CC-BY, нетлейблы, заказные треки.
  Отсюда устройство: студия ведёт **библиотеку треков** (аналог Featured Artists у osu!), маппер
  выбирает трек из неё, и набор получает `policy: included`. Политику ставит сайт, **никогда не
  загрузчик**.
- **Всё остальное — `external`.** Сайт хранит чарт, обложку и отпечаток аудио игрока (SHA-256, размер,
  длительность), но не сам файл. Мод никогда не скачивает аудио такого набора с qwu.world: это видно и
  в формате (`files` без OGG), и в регрессии (`external-audio package carrying audio` отвергается).
- **Произвольное аудио игроков сайт не хранит никогда**, ни «временно», ни «на проверку».
- **Передача аудио между игроками идёт мимо серверов студии**, и это должно быть прямо написано
  комментарием в коде, который её делает (`docs/LICENSING.md`, «Что это значит для кода», п. 4).
  Уже существующая передача через сервер Minecraft делает хостом владельца сервера, не студию.
- В моде и на сайте нет риперов YouTube, кнопок «скачать mp3» и маркетинга «играй любые треки».
- Обложки — тоже контент игроков: правила обложек и жалобы на них.

### Юридический стек до приёма загрузок

Сервер сайта не принимает **ни одной** загрузки (даже чартов и обложек), пока не готово
(`docs/LICENSING.md`, «Минимальный стек»):

1. ToS: гарантия прав, **явный грант лицензии** на хранение и раздачу, indemnity, право удалить.
2. Политика по рецидивистам и опубликованный канал жалоб: `copyright@qwu.world` + форма.
3. Регистрация DMCA-агента (6 $, на 3 года).
4. Шаблоны takedown и counter-notice.
5. EU DSA: электронная форма уведомлений (ст. 16), точка контакта.

**Форма жалобы и адрес должны работать до включения браузера карт в игре.** На Modrinth при первом
обращении мода к qwu.world нужно раскрытие (правило 1.11), при сборе статистики — Telemetry. «External
system interactions» не понадобится, пока мод не регистрирует ассоциации в ОС (вариант F не делаем).
Ни одного чужого трека в jar. Демо-OGG из `run/` (карта The Living Tombstone) никогда не используется
как стартовый контент.

### Статусы (аналог ranked-статусов osu!)

| Статус | Как попадает | Где виден |
|---|---|---|
| `pending` | Сразу после загрузки, пока идут автопроверки | Только автору |
| `community` | Прошёл автоматику: пакет валиден (тот же набор правил, что `BeatmapPackage`, портированный в TypeScript), аудио декодируется, лимиты соблюдены, нет дубля аудио-хеша, нет открытых жалоб выше порога | Каталог по фильтру «Community»; в игре за предупреждением по образцу `client.076-080` |
| `featured` | Выбран куратором QwU World, имя куратора на странице | Каталог по умолчанию; вкладка «Мастерская» в голосовании по умолчанию |
| `hidden` | Скрыл автор | Только автору и по прямой ссылке |

Роли: куратор (feature/unfeature, официальный комментарий) и модератор (скрыть, `disabled`, комментарии,
жалобы). На сайте уже есть `mod`/`admin`, куратора можно сделать флагом. Каждое действие пишется
в `audit`. BN/NAT-иерархия не нужна, пока кураторов двое-трое. Автоархив заброшенных черновиков

## Открытые вопросы к владельцу

1. **`external` и «свой» аудиофайл.** Точный SHA-256 надёжен, но у двух игроков файлы одной песни почти
   никогда не совпадают побайтно (разные рипы и кодирования). Варианты: (а) только точный хеш — честно,
   но мало кто сможет сыграть; (б) длительность ± допуск + ручная подстройка смещения — удобно, риск
   рассинхрона; (в) акустический отпечаток (Chromaprint) — надёжно, но сложно; (г) передача файла от
   игрока, у которого он есть, — юридически это вопрос к юристу (`docs/LICENSING.md`). Что выбираем?
2. **Кто загружает в первой версии:** только студия и кураторы или сразу все?
3. **Что делать с «Серверными» и «Пользовательскими» треками** и с публикацией через Minecraft
   (`user_tracks`): оставить чипами внутри «Мастерской», слить или вывести из обращения после запуска?
4. **Вкладка «Мастерская» в голосовании:** только наборы, установленные на сервере, или любой Featured
   по запросу (сервер сам скачивает, нужен исходящий HTTP у выделенного сервера)?
5. **Вкладка «Установленные» в голосовании:** можно ли предлагать свою карту на любом сервере или только
   там, где админ это разрешил?
6. **Клавиша по умолчанию:** решено — Alt+B (Option+B на Mac), переназначаемая.
7. **Гости:** листать без аккаунта? Скачивать без аккаунта (лимит по IP) или только с ним, как в osu!?
8. **Оценки:** 1–10 как у osu!, 5 звёзд или «нравится / не нравится»? Согласен ли владелец на то, что
   мод сообщает сайту факт прохождения карты (телеметрия, раскрытие на Modrinth)?
9. **Что ещё может лежать в наборе:** DJ-сценарии, чарты только с FX, видеофон? Если да, поле `mode`
   лучше добавить в формат 1 до первого публичного пакета.
10. **Снятая карта у тех, кто её уже скачал:** оставить, спрятать из голосования или удалить?
    Рекомендация: не удалять файлы игрока удалённо, только помечать.
11. **Подпись пакетов:** подписывать ли манифест ключом qwu.world (Ed25519 есть в Java 21), чтобы
    перетащенный файл показывался как «официальный» или «неизвестный источник»?
12. **Где живёт API мастерской:** в сервере сайта (у него база аккаунтов и форума) или в `qwu-api`?
13. **Имена, которые потом не поменять:** расширение `.blockymap`, числовой `setId`, id `ws_<setId>_<key>`,
    имя манифеста `beatmap.meta`, «Мастерская» / «Workshop» и «Установленные карты» / «Installed
    beatmaps» в интерфейсе. Подтвердить до первого публичного пакета.
14. **Лимит 16 чартов в наборе** — хватает? У osu! 128.
15. **Темп x1.5/x2** — это серверные перекодировки с другим хешем, поэтому «у меня уже есть» работает
    только на x1.0. Переносить ускорение на клиент? Это отдельная большая работа.
